# v0.1.4 — 全文OCR画像出力・Core 1.0.1同封版

保存した全文OCRを、元のページと同じ位置へ黒い文字で配置した白紙PNGとして出力できるようになりました。認識した文字の位置と内容を、原本と並べて確認できます。OCRやLLMを再実行せず、原本・保存済みOCR・既存のExcelも変更しません。

この版はWindows x64向けのPre-releaseです。PDFから一種類の項目を抽出する機能、mm座標付きExcel、モデル管理GUIを含みます。結果は未確認として扱い、利用者が原本と照合してください。

## 使い始める手順

1. `drawing-field-extractor-simple-v0.1.4-source.zip`を、書込み可能で十分な空き容量のあるフォルダーへ展開します。
2. ネットに接続し、`初期設定.bat`を実行します。取得する資産と利用条件を確認して、画面の案内に従ってください。
3. `input`へPDFを入れ、`前処理.bat`を実行します。
4. 全文OCRの配置を見たい場合は、`全文OCR画像出力.bat`を実行します。項目抽出が必要な場合は、`抽出設定.json`を設定して`抽出.bat`を実行します。

全文OCR画像出力は、最後に記録された前処理一覧のうち、検査に通った完成ページを対象にします。出力PNGは保存原画像と同じピクセル数・実寸・向きを保ち、毎回新しい`data/ocr-images`内の実行フォルダーへ保存します。ページごとの成功・失敗、領域数、フォント、警告は`export.json`に残します。空の正常OCRページは白紙PNGとして出力し、破損・未完了ページは失敗として記録します。

## 配布物と初期設定

このZIPはソースと取得処理をまとめた配布物です。構築済みruntimeやモデルを含む完成済み実行パッケージではありません。初期設定でPython公式の5 MSI、固定した91の外部Python wheel、OCRモデル、Ollama、Gemma4を取得し、展開したフォルダー内に配置します。通常のPythonやOllamaの設定は変更しません。GPU版Paddleを使うため、対応するNVIDIA GPUとドライバーが必要です。

自作のDocuWorks Core 1.0.1は、[dw-ocr v0.8.1で公開したMIT版](https://github.com/gogobousousannrinnsha/dw-ocr/releases/tag/v0.8.1)のwheelを変更せず同封しています。初期設定はSHA-256を確認し、ZIP内のwheelから導入します。MIT本文と著作権表示を保持しています。DocuWorks本体、SDK、専用DLL、Integrationsは同封していません。

文字の描画にはWindowsに導入済みのフォントを使い、配布ZIPにはフォントを同封しません。外部から取得するソフトウェア・モデルには、それぞれの条件が適用されます。詳しくは`THIRD_PARTY_NOTICES.md`と`licenses`を参照してください。

## この版で確認したこと

- CPU試験264件・35 subtestsが成功しました。
- 保存済みの実OCR4ページ・442領域から白紙PNGを出力し、実際のBATの終了コード0を確認しました。この試験は保存結果からの出力で、新たなOCR認識試験ではありません。
- 原本・保存画像・OCRのSHAが変わらず、OCR・LLM・SDKを再実行しないことを確認しました。
- 文字の位置・回転・白背景・px/mm寸法、空のOCR、保存破損・中断・既存出力の保護を検査しました。A0・A1の実寸300dpi相当の画像出力は、合成OCRで確認しました。
- 配布ZIPのCRCと全収録ファイルのSHAを検査し、Coreのwheelが固定した公開配布物と同一であることを確認しました。

## 制限と未検証

現在の入力はPDFのみです。Coreの同封は、XDW読込み機能の実装・動作確認を意味しません。

白紙PNGは未確認のOCR原文を表示します。誤認識もそのまま残り、元の図形・罫線・書体や縦書きの組版は再現しません。PNG上の文字は編集可能な文字データではありません。対応フォントがない場合や極端に小さい文字には、失敗または警告を記録します。

今回の追加検証は保存済みOCRからの画像出力が対象です。v0.1.4での完全な新規オンライン構築からGPU OCR・LLM・Excelまでの通し処理と、Gemma4／Gemma3の既存19課題の精度回帰は再実施していません。業務図面の精度と別PCでの動作も未検証です。以前の版の検証結果とは区別してご利用ください。
