# 図面項目抽出 簡素版 v0.1.5 — PDF/XDW共通OCR・Excelから黄色マーカー

複数のPDF／XDW図面から、指定した一種類の項目を抽出し、mm座標付きExcelへ出力するローカルアプリです。OCR結果を保存して再利用し、項目やモデルを変えて抽出し直せます。出力内容は未確認として扱い、人が原本と照合して修正します。

`全文OCR画像出力.bat`で、保存済みの全文OCRの文字を、元のページと同じ位置に配置した白紙PNGを出力できます。抽出した項目だけでなく、認識した全文を黒い文字で表示します。OCRやLLMを再実行する必要はありません。

ソースZIPには自作コード、取得処理、自作のDocuWorks Core 1.0.1を収録しています。実行環境とモデルは、最初の`初期設定.bat`で公式配布元から取得します。CoreはZIP内のwheelから導入し、ネットから取得しません。既にインストールされたPythonやOllamaの設定を変更せず、展開したフォルダー内に配置する構成です。

v0.1.5は、PDFとXDWの共通OCR、Hugging Faceからのモデル代替取得、抽出ExcelからXDWへの黄色マーカー配置をまとめたWindows x64向けPre-releaseです。`黄色マーカー追加.bat`は、指定XDWに対応する座標のある全行を読み、原本のコピーへ黄色・透過のDocuWorksマーカーを配置します。モデル取得時にOllamaで失敗した場合は、固定したHugging Face版を別のモデル資産として取得し、動作確認後に採用します。

## 同封するCore

`bundled/core/docuworks_ctypes-1.0.1-py3-none-any.whl`は、[自作Coreの公開MIT版（dw-ocr v0.8.1）](https://github.com/gogobousousannrinnsha/dw-ocr/releases/tag/v0.8.1)の配布物です。初期設定は同封wheelのSHA-256を検査して、フォルダー内runtimeへ導入します。版、取得由来、サイズとSHAは`assets/bundled-core.json`に記録します。CoreのPythonコードとMIT本文はwheel内に保持しています。Integrationsは同封しません。

XDW入力時はCoreを使ってページ実寸を取得し、ページを画像化します。DocuWorks本体、SDK、専用DLLは同封しません。**XDWの前処理には、利用者が正規に導入した互換性のあるDocuWorks環境が必要です。** PDFの前処理ではDocuWorks DLLを読み込みません。

## XDW入力の扱い

`input`へPDFとXDWを混在して置けます。前処理は元の拡張子を保って原本コピーを保存し、XDWは保存したコピーを読み取り専用で開いて各ページを300dpiのPNGへ変換します。PDFは従来のPDFiumで画像化します。どちらもページ番号・PNG・px寸法・ページ実寸mmを共通の形式に揃え、その後のGPU OCR、AI抽出、Excelと全文OCR白紙PNG出力を共用します。

文字領域のmm座標はページ実寸と生成画像の実際のpx寸法から換算します。保存記録には入力形式と画像化条件を残し、XDWではCore／DocuWorksの版も記録します。原本や処理条件が一致しないOCRを再利用しません。DocuWorks環境が利用できない場合、開けないXDWや画像化に失敗したページは、理由付きの失敗として記録します。

XDW入力と原本コピーへの黄色マーカー追加に対応します。XDWへのOCRテキスト書込み、校正取込、バインダー（XBD）入力は含めません。実SDKでの検証と、Viewer操作・実務図面の精度確認は区別しています。機能別の確認済み範囲と未検証範囲は[検証状況](docs/VERIFICATION_JA.md)を参照してください。

## 最初に使うとき

1. ZIPを、書込み可能で十分な空き容量があるフォルダーへ展開します。
2. ネットに接続し、`初期設定.bat`を実行します。取得する資産と利用条件を確認し、画面の案内に従います。
3. 完了後に`モデル管理.bat`を開き、Gemma4が動作確認済みで、現在の使用モデルになっていることを確認します。公開用の初期設定はGemma4を選択しています。
4. `input`へPDF／XDWを入れ、`抽出設定.json`に項目を記入します。XDWを使う場合は、互換性のあるDocuWorks環境を導入しておきます。
5. `前処理.bat`、続いて`抽出.bat`を実行します。Excelを原本と照合して確認・修正します。
6. XDWへ抽出位置を示す場合は、`黄色マーカー追加.bat`で出力Excelと原本XDWを選びます。原本を保持した別XDWを保存します。

全文OCRの配置を確認したい場合は、`前処理.bat`の後で`全文OCR画像出力.bat`を実行してください。`抽出.bat`を先に実行する必要はありません。新しく展開した候補は、通常どおり初期設定と前処理を行います。以前の候補で作成した保存済みOCRを使う場合は、対応する原本・画像・OCR・前処理記録を含む`data`一式が必要です。OCRのJSONだけを移しても出力できません。

初期設定の中断後は、同じフォルダーで`初期設定.bat`を再実行します。完成した取得物はSHAで検査して再利用します。取得失敗やハッシュ不一致を無視して処理を完了させません。通信に制限がある環境では、公式配布元への接続を確認してください。

## Ollamaからモデルを取得できないとき

初期設定とモデル管理の導入処理は、まず専用Ollamaから取得します。HTTPエラー、通信エラー、取得途中のエラー、正常完了の記録がない場合は、固定したHugging Face版の本体と画像用部品を直接取得します。取得元のrevision、ファイルサイズ・SHAを固定し、Ollama版とは別のmanifest digestで識別します。ダウンロード後も全SHA、Ollamaの認識、画像・Thinking等の対応、サーバー終了を検査します。初期設定では、その後に従来の画像付き動作確認を行い、画像と構造化出力を検査します。これに通るまで使用可能な確認済み状態にはしません。

Hugging Faceにも接続できない場合、固定版を取得できない場合、取得内容が破損している場合は、理由を表示して停止します。初期設定のモデル段階は`data/setup-complete.json`へ`failed`として記録し、終了コード1を返します。初期設定完了や、未確認モデルの使用状態にはしません。使用中のモデル・選択設定・以前の導入記録を取得失敗で上書きしません。中断、容量不足、利用条件未確認の場合は代替取得を開始しません。`--offline`指定でもネット取得は行いません。

取得先とモデル定義は`assets/huggingface-ollama.json`に保持しています。代替取得はggml-orgのGemma4 E4B Q8とGemma3 4B Q4_K_Mを対象とします。本体と画像用部品の取得元を40桁のrevisionへ固定し、二種類の資産をそれぞれのSHAで識別します。モデル管理の一覧にHugging Face版と表示し、導入記録にも取得元・revision・実際のdigestを残します。Ollama版での以前の動作確認を、Hugging Face版の確認として再利用しません。モデル管理から導入した場合は、従来どおり動作確認を通してから選択してください。

Hugging Face取得では`HTTPS_PROXY`等の環境変数を引き継ぎ、WindowsのcurlでTLS証明書を検査します。証明書検査を無効にしたり、プロキシ設定を自動変更したりしません。接続は30秒、転送停滞は60秒で失敗とし、モデル本体の一回の転送上限は1時間です。途中ファイルは保持し、次回に再開できる場合は再利用します。

基準となるモデル取得代替経路版v0.1.5では、CPU試験359件と35件のサブテストが成功しました。実ジャンクションを作る1件は環境の権限制約で未実施です。小さい人工ファイルと模擬通信で、取得・停止・中断・整合性・旧合格記録の流用防止を確認しています。

Gemma4のHF版は、独立フォルダーへ本体約8.03GBと画像用部品約0.99GBを実際に取得し、全SHA、Ollama認識、画像・Thinking・JSONの動作、確認後の選択、モデル解放・専用サーバー終了まで確認しました。画像とOCRによる二つの自作試料で、部品番号`001-020`と根拠IDの一致、および記載がない項目を`not_found`とすることを確認しています。Ollama側の失敗は人工的に発生させたものです。実際の企業プロキシ、Gemma3のHF実取得・推論、実務図面の精度回帰は未検証です。このHF取得経路の検証時には、新しいOCRの通し処理は未実施でした。PDF／XDWの通し処理は、その後の共通OCR候補で人工資料を使って別途確認しています。以下の過去版の結果を、この版で新たに実施した結果として扱わないでください。

初回取得と任意モデルの導入にはネット接続が必要です。必要な資産の構築後は、画像・OCR・モデルをこのフォルダーから読み込んで処理します。アプリの処理はローカルです。初期取得後の通信の有無を厳密に確認したい場合は、使用環境側でもネット接続を制御してください。

## 六つの入口

| 入口 | 処理 |
|---|---|
| `前処理.bat` | 指定フォルダー直下のPDF／XDWを保存し、実寸300dpiのPNGと全文OCR・px/mm座標を作成 |
| `全文OCR画像出力.bat` | 保存済みの全文OCRを元の位置に配置し、白紙のページPNGとして新しく出力。OCRやLLMは再実行しない |
| `抽出.bat` | 保存画像・全文OCRと設定から一種類の項目を抽出し、新しいrunへJSON・Excelを保存 |
| `Excel再出力.bat` | 保存済みの抽出結果からExcelを新しく生成。OCRやLLMは再実行しない |
| `黄色マーカー追加.bat` | 抽出Excelの全対象座標行を使い、指定XDWのコピーへ黄色・透過のマーカーを追加。OCRやLLMは再実行しない |
| `モデル管理.bat` | Gemma4／Gemma3の導入状態・動作確認・次回使用モデルの選択 |

入力先は`実行設定.json`の`input_folder`で指定します。初期値は`input`です。サブフォルダーを再帰検索しません。原本や画像化・OCR条件を変えた場合は、前処理から実行してください。抽出項目・位置ヒント・モデルだけを変える場合は、保存済みの画像とOCRを使います。

## 全文OCR画像の見方

`全文OCR画像出力.bat`は、最後に記録された前処理のPDF／XDW一覧を使います。完成した保存ページの原画像とOCRを検査し、認識文字を同じページ位置へ配置します。途中のページに失敗がある前処理でも、検査に通った完成ページを出力できます。

出力先は毎回新しい`data/ocr-images/<実行ID>/<文書番号と安全な名前>/page-0001.png`です。ページごとに一枚のRGB PNGを作り、保存原画像のピクセル数、ページ実寸mmと向きを維持します。白地に黒いOCR原文を配置し、認識スコアによる足切りは行いません。元の図形、罫線、写真は描き直しません。

**この画像は未確認の認識結果を位置とともに見るためのものです。** 誤認識もそのまま表示します。文字の向きは保存された四隅の順から決め、縦書きの組版や元の書体は再現しません。PNGに描いた文字は編集可能な文字データではありません。原本と併せて確認してください。

文字の描画には、Windowsに導入済みのフォントを使います。日本語フォントを優先し、認識文字に対応していなければ、PC内の日本語・CJKフォントから全文を表示できるものを選びます。配布ZIPにフォントは同封しません。利用できるフォントが見つからない場合は、理由を表示して失敗として記録します。対応フォントがない文字や、極端に小さくなる文字には、画面とJSON記録へ警告を残します。

出力ごとの`export.json`に、各ページの成功・失敗、配置した領域数、空文字の領域数、フォント、警告と出力先を残します。文字が一件も認識されていない正常ページは、白紙PNGを作り、配置件数0として記録します。保存結果の破損や未完了ページを、文字がない正常ページとして扱いません。一部ページに失敗があれば他のページを続け、終了コード2を返します。

この操作では原本、保存画像、OCR、抽出結果、既存Excelを変更しません。再実行時は別の出力フォルダーを作ります。CoreやDocuWorks SDKを使わず、保存済みのPDF／XDW前処理結果から出力します。

## 抽出設定

```json
{
  "item": "部品番号",
  "region_hint_mm": null,
  "take": "one",
  "instruction": ""
}
```

`take`は、各ページから一つ取得する`one`、または該当する記載をすべて取得する`all`です。`region_hint_mm`は任意の探索の目安で、`{"x":200.0,"y":150.0,"width":80.0,"height":40.0}`のように記入します。ページ左上原点、xは右、yは下、単位はmmです。幅と高さは右端・下端の座標ではありません。範囲外の画像やOCRを切り捨てる指定ではありません。

## モデルと初回確認

初期設定は自作PDFの実OCR確認と、`gemma4:e4b-it-q8_0`の導入、digest・資産の検査、小さな画像・OCR試料による接続確認を自動実行します。この確認が成功してから初期設定を完了します。再実行時は利用者が変更したモデル選択を保持します。Gemma3は`モデル管理.bat`で規約と禁止用途を確認・受諾してから任意導入できます。導入済みと動作確認済みは別の状態です。

対応するGUIモデルはGemma4とGemma3の二種類です。任意のタグやGGUFをGUIへ追加する機能は含めません。Salukiの既存コードは残していますが、初期設定でSaluki資産は取得しません。

Salukiを追加したい場合は、初期設定後に`Saluki追加設定.bat`を実行します。固定版のモデル・画像用モデル・llama.cppと必要な通知を公式配布元から取得し、SHAで検査します。初回追加には22.5GiB以上の空き容量が必要です。この操作は`実行設定.json`や現在のモデル選択を変更しません。記録の`inference_verified`は`false`で、取得・配置の完了と推論確認を区別します。この取得方式でのSaluki推論はまだ未確認のため、追加完了を抽出動作の確認済みとは扱わないでください。

専用Ollamaは`127.0.0.1:11449`を使います。このアプリが起動したプロセスだけを終了します。モデル変更で再OCRは行わず、新しい抽出runを作成します。モデルの動作確認は技術動作を確認するもので、業務図面に対する精度保証ではありません。

## Excelの見方

主シート「未確認結果」は、原本ファイル、ページ、項目、値、備考、`x_mm`、`y_mm`、`width_mm`、`height_mm`、根拠ID、結果IDを出力します。「根拠座標」シートには、個別のOCR原文と矩形を出力し、結果IDで対応します。

座標はモデルが引用したOCR領域の位置です。値だけの範囲とは限らず、ラベルを含むことがあります。複数領域は、それらを囲む外接矩形を主シートへ出します。OCR根拠がない場合は座標を空欄にし、推測した座標を作りません。誤った根拠IDが選ばれれば、その領域の座標が出るため、原本との確認が必要です。

先頭ゼロや数式に見える文字は文字セルとして保存します。同じ値の別記載も残します。処理失敗や空結果にも理由付きの行を作ります。実行ごとに新しい出力を作り、修正済みExcelを上書きしません。

## Excelから黄色マーカーを付ける

`黄色マーカー追加.bat`をダブルクリックし、抽出Excel、原本XDWの順に選択します。「未確認結果」シートで、対応文書の`x_mm`・`y_mm`・`width_mm`・`height_mm`が揃う全行を対象にします。非表示行やフィルターで隠れた行も含み、座標のない行はスキップします。「根拠座標」は照合に使い、そこから重複配置しません。

対象XDWと同名の文書行は自動で選びます。改名した原本やPDF由来の座標を使う場合は、Excel内の対応文書を明示して選びます。対応XDWには同じ内容・ページ順・表示サイズが必要です。保存した抽出記録がある行は、原本SHA、結果ID、保存OCRの根拠・座標も照合します。XDW抽出時の原本と異なるXDWは拒否します。保存記録がないExcelは、対応文書の選択とページ・座標による照合として処理JSONに記録します。

出力は毎回新しい`data/markers`内のフォルダーに、`原本名_黄色マーカー.xdw`と`マーカー処理結果.json`を保存します。原本XDW・Excelは変更しません。表示ページのmm座標へ、線幅1～13ptの帯状マーカーを必要数配置し、保存・クローズ・再読込みで数・種類・色・透過・幅・座標を検査してから確定します。帯の端は丸く、線幅の整数ptへの丸めにより矩形の境界へ少しはみ出す場合があります。

数式、不正な座標、存在しないページ、ページ外の矩形、根拠の不一致はエラーで停止します。OCR根拠の矩形にはラベルが含まれる場合があり、黄色マーカーが抽出値だけの範囲になるとは限りません。詳しい操作とコマンド例は[黄色マーカーの使い方](黄色マーカー_使い方.txt)を参照してください。

## 保存と失敗

画像・OCR・抽出結果は`data`、診断は`logs`へ保存します。設定、入力、保存結果の一式が相対パスでつながるため、実行中のアプリを閉じてからフォルダー全体を移動してください。一部だけを移動すると再開や再出力に必要な資産を失います。

ページ失敗があっても他ページを続け、備考とJSONへ理由を残します。容量超過、HTTP失敗、タイムアウト、生成上限、JSON不成立を「記載なし」へ置き換えません。正常終了は終了コード0、一部失敗は2、中断は130です。中断時は完成ページを保存し、Excelを作らず、同一条件の未処理ページから再開します。

上限は対象PDF／XDW合計1,000ページ、ページ画像6億画素です。この上限内でも、密集図面ではモデルの入力容量を超える場合があります。

## 公開ZIPを作る人向け

`scripts/build_source_zip.py`は許可したテキストのソース・取得処理と、固定したCore 1.0.1のwheelだけを収録します。Coreは配布物全体のSHAと内部ファイルを検査し、任意のwheelを追加できる仕組みにはしません。runtime、第三者DLL、モデル、取得キャッシュ、図面、OCR、Excel、ログ、検証コピー、鍵、Git情報は収録しません。ファイルSHAの一覧とZIPのSHAを作り、再読込みで一致を検査します。

```powershell
python scripts/build_source_zip.py
```
